# PROTOCOLS · 协议合订

> 系统运行的全部协议，一页读完。细则出处：`docs/METHOD.md`（原则）/ `docs/SSMAP.md`（台账）。

## 三不变量

1. **原文不可变** —— 已写下的记录不删改；更新走追加（登记册例外：收尾时更新自己那行）
2. **单向提纯** —— `inbox/` → `knowledge/` / `lines/`，永不反向
3. **一个事实一个家** —— 一个事实只写一处；别处放指针（见 METHOD §1）

## 写入协议（inbox）

行格式：
```
- YYYY-MM-DD [fact|decision|insight|assertion|state] 内容 | source: <出处> | line: <线索> | owner: <谁定的> | conf: <实测|推断|待核>
```
- `fact` 必带 source；`decision` 必带 owner；无出处 = 无效行
- `conf` 可选但推荐给关键数字：实测/推断/待核；缺省=未标，不计入覆盖率
- 只追加，不改已写行；提纯后在原行尾加 `→ 归位:<目标>`（放在 `| conf:` 之后也可以）
- 计数口径：`ssot_check` 把「以 `- ` 开头且整行不含 `→`」的行计为未提纯——正文里自带箭头（如 `A → B`）的行会被判成已提纯，别在正文用箭头，或先补 `→ 归位:` 标记
- conf 覆盖率单算：值须以 实测/推断/推算/待核 开头（允许「实测（口径…）」限定语）；判定前先剥掉行尾 `→` 标记
- **conf 归一化（v0.11.0）**：`源码/设备实测/代码/单测` 等常见写法归一到 `实测`；`决定/用户令/owner` 是“谁定的”，不是置信度，不参与 conf，也不报非法值

## 台账协议（开工三问 / 收尾一行）

- **开工三问**：①搜 `sessions/registry.md` ②有线 → 读 `lines/<线>.md` 的【在途】【续点】→ 默认接续 ③无线 → 新开+补账
- **收尾一行**：更新登记册自己那行（状态+干到哪了）
- 口径：同线同目标→接续；目标变/上下文脏/跨系统→新开并引用旧结论（细则见 SSMAP §五）

## 薄壳协议（记忆装载）

- **常驻上下文必须极短**：agent 记忆只放「指针 + 行为纪律」（薄壳），细节按需读（拉不推）
- 薄壳是**编译产物**：正本在 `~/ssot`，用 `tools/sp_compile.py --mem` 生成；**勿手改产物**
- 正本变更后重编译即下发；改行为纪律 → 改 `profile/harness-boot.md`

## 检索协议（拉不推）

- 回忆词（以前/上次）/接手一条线/疑难取证 → **先查再答**
- 顺序：台账/线页 → grep → （如装了语义层）`sp_semantic.py`
- 不把长文常驻进上下文

## 子 agent 检索（2026-10-21）

子 agent **不继承** SessionStart hook 与开机块。派单时 brief 必须显式带：

1. 检索规则（回忆/取证先查 `sp_semantic.py`）；
2. 本任务相关的 1–3 个 `path:line`；
3. 只动点名文件。

主会话收口时记录「用了哪些源」；检索为空也要写「未命中」——没有记录的检索不算发生。

## 发布/交接门禁（2026-10-21）

发布文章、交接一条线之前，先确认当前会话在登记册有行：

```bash
bash ~/ssot/tools/session-gate.sh publish --sid <会话id>
bash ~/ssot/tools/session-gate.sh handoff --sid <会话id>
```

退出码：0=有行；1=无行（先补 registry）；2=无法验证（缺 sid/registry）。门禁是提示与阻断的工具，不替你写台账。

## 存量记忆处置（v0.3 起旧 `*.md` 已冻结为档案）

已有大量 agent 记忆（如 `~/.qoder/memory/*.md`）的机器，三选：

1. **冻结 + 保留**（最小动作）：文件原样不动，只作档案按需 grep；薄壳不再引用它们。
2. **冻结 + 索引**（默认推荐）：不动文件，另建第二个向量库，检索时双库查询：
   ```bash
   python3 ~/ssot/tools/sp_index.py --root ~/.qoder/memory --db ~/ssot/kb-index/kb-memory.db
   python3 ~/ssot/tools/sp_semantic.py "…" --db ~/ssot/kb-index/kb-memory.db
   ```
   敏感条目先在 `~/.qoder/memory/.kbignore` 写排除 pattern（`.kbignore` 只看 `--root` 根）。
3. **渐进提纯**：按价值逐条搬到 `~/ssot/inbox/` → 提纯到 `knowledge/` / `lines/`；旧文件保留但不再增长。

三种都不删除原件；迁移只做加法。

## 脚本改写纪律（2026-10-16 下游事故后立）

- **读→改→写分离**：脚本改写既有文件必须「全量读 → 内存改 → 单次写」。
  `open(p,'w').write(open(p).read()...)` 会因求值顺序**先截断后读** → 文件清空。
- **长任务完成判据 = 制品侧四证**（产物存在/数量对/内容抽样对/退出码 0），不是日志末尾；
  不要用 `| tail` 包长任务（管道会掩盖 exit code，制造「假绿」）。

## 会话协议（本次会话怎么收场）

- 会话干完活：登记册记一行（见上）；重大结论写 `inbox/`
- 长时间会话：阶段产出**边做边落**（会话会被压缩，只在聊天里说的等于没说）
- 接手别人的线：先读该线页全文再动手（线页自包含）

## 纪律红线

- **只 pull 永不 push**（下游）；内容层永不外发
- 外发/发布类不可逆动作：逐批显式确认后再做
