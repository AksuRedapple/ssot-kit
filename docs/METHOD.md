# METHOD · 五条核心原则

> 这套系统的全部设计都从五条原则推导出来。改系统前先读这页。

## 1. 单一真源（一个事实一个家）

每个事实只写进**一个**文件；其他地方只放**指针**，不复制内容。
反例：同一个结论在三处各写一份——三份都会漂移，最后不知道信谁。
推论：台账行、线页、知识条目，各有明确归属（见下方布局）。

## 2. 台账先于对话（开工三问）

开始一条线的任何新需求前，先走「开工三问」（搜登记册 → 读线页 → 指向续点）。
**新开还是接续，由台账决定，不由手感决定。** 台账是入口，对话是工作面。

## 3. 收尾一行

每个会话干完活时，往登记册更新自己那一行（状态 + 干到哪了）。
台账的价值 = 行情的鲜度；**不记账的会话等于没发生过**（下次找不到）。

## 4. 拉不推（检索按需）

知识按需读取：开工时读**相关**的线页，需要细节再用检索。
不把长文常驻进上下文——上下文是预算，塞满即成噪声。
（这也是「开机块」只放约十条纪律的原因：常驻内容必须极短。）

## 5. 出处纪律

写进台账/知识条的结论带**去处**（来源会话/文件）；决策带**是谁定的**。
没有出处的结论 = 下次没人敢信、没人敢用。

## 布局（实例根，各机同名同构）

```
~/ssot/
├── START.md               读档入口（一页纵览）
├── lines/                 业务线页（每线一页，含【续点】）
├── sessions/registry.md   会话登记册（一行一会话；开工三问第一站）
├── knowledge/             断言库 / 术语表 / topics/ 主题结晶 / open-loops 未尽工作
├── inbox/                 新知识入口（fact 带 source / decision 带 owner）
├── profile/               开机块（harness-boot.md）等
└── tools/                 工具（编译薄壳 / 语义索引检索 / 自查）

<系统件仓库>/          上游下发的系统件（位置见 ~/ssot/profile/.kit-path；git pull 升级，见 UPGRADE.md）
```

> 机器角色：**macmini = 上游**（迭代系统件 → 发布）；**工作机 = 下游**（只 pull，不回推）。
> 内容层（lines/knowledge/inbox/sessions）**永不离开本机、永不入仓**。
