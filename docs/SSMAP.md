# SSMAP · 会话台账协议细则

> 一句话：**台账让「接哪一个会话」这个问题有一个查得到答案的地方。**
> 台账落在实例里：登记册 = `~/ssot/sessions/registry.md`；业务线页 = `~/ssot/lines/`。

## 一、登记册格式（`~/ssot/sessions/registry.md`）

一行一会话，追加为主：

```
- YYYY-MM-DD ｜ <业务线> ｜ <主题一句话> ｜ 状态:进行中/已结/搁置 ｜ <干到哪了> ｜ 指针:<会话 id 或唯一定位词>
```

示例：
```
- 2026-10-16 ｜ 订单改造 ｜ 拆分支付回调 ｜ 状态:进行中 ｜ 方案已定稿，代码改到 60% ｜ 指针:会话 a1b2c3
- 2026-10-12 ｜ 订单改造 ｜ 回调超时排查 ｜ 状态:已结 ｜ 根因=下游重试风暴，已加限流 ｜ 指针:会话 d4e5f6
```

规则：
- 「状态」只有三种：`进行中` / `已结` / `搁置`
- 「干到哪了」写**给下一次的自己看**：一句说得清"从这继续要做什么"
- 会话更新状态 = 修改原行（收尾一行），不要重复追加同一会话

## 二、业务线页（`~/ssot/lines/<线名>.md`）

每线一页（模板见 `instance/lines/_template.md`），字段固定：

```markdown
# 线：<线名>
> 状态: 进行中/已结/搁置 — 最近: YYYY-MM-DD

## 一句话
## 当前在途
- [ ] <下一件要做的事>
## 关键决策记录
- YYYY-MM-DD <决策>（谁定的）
## 相关会话
- YYYY-MM-DD <主题>｜指针:<id>
- **【续点】** <最新会话>（下次接续从这里进）
## 相关文件
- <本机路径/资料位置>
```

「续点」= 这条线**当前应该接续的会话**；该线有新会话在跑时，续点跟着移动。

## 三、存量普查（一次性）

1. 枚举会话（`python3 ~/ssot/tools/scan_sessions.py` 或工具自带的会话列表）
2. 聚类到业务线（= 持续推进的工作主题；拿不准的先并列到「待归类」）
3. 草稿登记册 + 线页；给用户「总览」（几条线/每线几会话/哪些拿不准）
4. **停下等用户确认** → 定稿
5. 先只写「近 30 天活跃」的会话；更老的在线页「相关会话」折叠一行提及（普查不是考古，目标是把「活账」建起来）

## 四、两条回路（日常）

**开工三问**（每次开展新需求时）：
1. 在 `registry.md` 搜相关词 —— 有没有已存在的线？
2. 有 → 读该线页的「当前在途」与【续点】→ 默认去续点会话接续
3. 没有 → 新开：补登记册一行、建线页（或挂到最相近的线）

**收尾一行**：
更新登记册里自己那行（状态 + 干到哪了）；线页「在途/续点」有变化随手同步。

## 五、新开 / 接续口径

| 情况 | 动作 |
|---|---|
| 同线、同目标 | **接续**（进【续点】会话） |
| 目标变了 / 上下文太脏 / 跨了系统 | **新开**，且把旧会话的关键结论摘要作为新会话开场引用 |
| 完全新的主题 | **新开**建线 |

## 六、维护纪律

- 谁最后碰的谁更新（没有专职管理员）
- 登记册与线页以「查得到」为底线，不以「写得好」为门槛
- 全部内容留在本机：**永不推送、永不外发**
